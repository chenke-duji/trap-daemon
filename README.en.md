# trap-daemon

> **Language / 语言**: [中文](README.md) | English

A high-performance, multi-threaded SNMP Trap Daemon. It receives SNMP Traps
(v1/v2c) from network devices, maps varbind OIDs to field names using the OID
database generated by mib-parser, builds the `RawEvent` JSON required by
cep-engine, and forwards it in batches to cep-engine over REST HTTP. It is
designed for **Active-Active** multi-instance deployment (deduplication is
handled by cep-engine's TransportDeduplicator; the daemon itself is stateless).
Kafka is reserved as an optional forwarding channel.

## Features

- **SNMP Trap reception**: listens on UDP 162, parses v1/v2c, with a reserved
  v3 extension point
- **OID → field-name mapping**: loads `oid-database.db` (mib-parser
  output) and does longest-prefix matching of full instance OIDs to field names
- **RawEvent construction**: strictly aligned with the cep-engine ingestion contract
- **REST batch forwarding**: worker-pool batching POST to
  `/api/v1/events/batch`, exponential-backoff retry, bounded-queue backpressure,
  drop-with-log when the queue is full
- **Active-Active**: stateless multi-instance, dedup handled by cep-engine
- **Self-monitoring**: Prometheus text-format `/metrics` with start time, total
  traps, and last-5-minute throughput
- **Configuration**: YAML + environment-variable overrides

## Architecture

```
Devices --SNMP v1/v2c Trap UDP:162--> trap-daemon
                                       |
                 ┌─────────────────────┤
                 ▼                     ▼
        gosnmp TrapListener      OID map(oid-database.db)
                 │                     |
                 ▼                     |
              TrapDecoder ────────────┤  varbind OID -> field name
                 ▼                     |
             RawEvent build ──────────┘
                 ▼
        BatchQueue(worker pool + backpressure)
                 ▼
        POST /api/v1/events/batch ──> cep-engine
                                          |
                                          ▼
                     TransportDeduplicator(Active-Active dedup)
                                          ▼
                     Groovy parser -> alarm
```

## Build

Requires Go 1.22+ (dev env 1.26.7).

**Windows (local build)**

```bat
go build -o bin\trapd.exe .\cmd\trapd
```

**Windows cross-compile for Linux** (pure Go, no cgo needed)

```bat
set CGO_ENABLED=0
set GOOS=linux
set GOARCH=amd64
go build -o bin\trapd-linux-amd64 .\cmd\trapd

set GOARCH=arm64
go build -o bin\trapd-linux-arm64 .\cmd\trapd
```

**Linux / WSL**

```bash
# local platform
go build -o bin/trapd ./cmd/trapd

# cross-compile Linux x86_64
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o bin/trapd-linux-amd64 ./cmd/trapd

# cross-compile Linux aarch64
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o bin/trapd-linux-arm64 ./cmd/trapd
```

Or use `make` (requires make under Git Bash / WSL on Windows):

```bash
make build              # local platform
make build-linux-amd64  # Linux x86_64
make build-linux-arm64  # Linux aarch64
make build-linux        # amd64 + arm64
```

The produced binaries are **statically linked** (CGO_ENABLED=0), with no shared
library dependencies, and can be deployed to any x86_64/aarch64 Linux
distribution. Verified on WSL AlmaLinux-8 with a native Go 1.27.0 build and a
real v2c trap end-to-end (receive → field mapping → RawEvent → HTTP forward).

## Configuration

Copy `config.example.yaml` to `config.yaml` and fill in:

- `oidMap.path`: **required**, points to the `oid-database.db` generated
  by mib-parser (this project does not bundle the file). Update and persist the
  file whenever mib-parser adds MIB support, then restart the daemon.
- `cepEngine.baseUrl`: **required**, the cep-engine root URL.
- All other fields have defaults.

Environment overrides (higher priority than YAML):

| Env var | Description |
|---|---|
| `TRAPD_SNMP_LISTENADDR` | UDP listen address |
| `TRAPD_SNMP_PROTOCOL` | `v1v2c` / `v3` |
| `TRAPD_SNMP_COMMUNITY` | optional community |
| `TRAPD_OIDMAP_PATH` | OID database path |
| `TRAPD_CEPENGINE_BASEURL` | cep-engine root URL |
| `TRAPD_CEPENGINE_AUTHTOKEN` | Bearer token |
| `TRAPD_LOGGING_LEVEL` | log level |
| `TRAPD_LOGGING_FILE` | log file path |
| `TRAPD_METRICS_ENABLED` / `TRAPD_METRICS_LISTENADDR` / `TRAPD_METRICS_PATH` | self-monitoring |

## Run

**Linux / WSL**

```bash
./bin/trapd --config config.yaml
```

Listening on port 162 as a non-root user requires privileges; either change
`snmp.listenAddr` to `:1162` (and use that port in cep-engine collection) or run
as root/systemd.

**Windows**

```bat
bin\trapd.exe --config config.yaml
```

On Windows, listening on 162 also needs an elevated (Administrator) process, or
use `:1162`.

Full deployment guidance (Windows service, Linux systemd, Active-Active
multi-instance, WSL native build) is in
[`DEPLOY.md`](DEPLOY.md) (Chinese) and [`DEPLOY.en.md`](DEPLOY.en.md) (English).

## cep-engine contract

The `RawEvent` JSON built by the daemon (field names strictly matching
cep-engine `com.raysdata.cep.model.RawEvent`):

```json
{
  "source": "snmp_trap",
  "sourceIp": "192.0.2.10",
  "receivedAt": 1724400000000,
  "originTimestamp": 1724399999000,
  "rawEvent": "SNMP trap v2c from 192.0.2.10\n...",
  "metadata": {
    "trapOid": "1.3.6.1.6.3.1.1.5.3",
    "varbinds": {"ifIndex": "3", "ifDescr": "eth0"}
  }
}
```

Key points:

- **`varbinds` keyed by field name**: aligned with the generated parser's
  `varbinds.get(fieldName)`. If an OID cannot be mapped to a known field name,
  the full instance OID is kept as the key (cep-engine's `resolveInstanceOid`
  falls back to full instance OIDs).
- **Deterministic `originTimestamp`**: derived from the trap's `sysUpTime`
  (v1/v2c carry no device absolute time), so identical events from multiple
  Active-Active instances produce the same `originTimestamp`, matching the
  cep-engine fingerprint `source+sourceIp+SHA-256(rawEvent)+originTimestamp` for
  cross-instance dedup.
- **Deterministic `rawEvent`**: does not contain `receivedAt`, safe for the
  dedup fingerprint.

## Active-Active deployment

1. Deploy 2+ trap-daemon instances, each listening on UDP 162 (different hosts,
   or load-balanced/anycast trap distribution).
2. All instances point to the **same** cep-engine and the **same**
   `oid-database.db`.
3. Each instance forwards the same trap to cep-engine; cep-engine's
   `TransportDeduplicator` (TTL 10s) drops duplicates.
4. No leader election, no failover delay; an instance outage does not affect
   other instances.

## Self-monitoring metrics

Prometheus scrapes `GET :9091/metrics`:

| Metric | Type | Meaning |
|---|---|---|
| `trap_received_total` | counter | total traps received |
| `trap_forward_total` | counter | total events forwarded successfully |
| `trap_forward_failed_total` | counter | total failed forwards |
| `trap_dropped_total` | counter | total dropped (queue full) |
| `queue_depth` | gauge | current queue depth |
| `trapd_start_time_seconds` | gauge | process start time (unix) |
| `trap_throughput_5m` | gauge | avg throughput over last 5 min (events/s, sliding) |

5-minute throughput: `rate(trap_received_total[5m])`, or read
`trap_throughput_5m` directly.
